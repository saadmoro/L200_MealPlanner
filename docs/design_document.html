1. Executive Summary

This design specifies an agentic grocery store meal-planning and shopping-list application built on Google ADK 2.0. Following a determinism-first philosophy, all database lookups, allergen and sodium safety checks, serving-size scaling, macronutrient/calorie calculations, SKU package rounding, and order persistence are executed by typed Python FunctionNodes and FunctionTools. Probabilistic LlmAgent calls are isolated to conversational discovery and skill-calibrated recipe authoring.

Safety & Clinical Boundaries: Medical constraints (e.g., celiac disease / gluten, hypertension / sodium) are enforced deterministically at both the tool/SQL layer and a runner-wide DietarySafetyPlugin (BasePlugin), accompanied by a non-medical-advice disclaimer.

2. Agentic Workflow DAG & Data Flow

The root agent is an ADK 2.0 google.adk.workflow.Workflow configured with ResumabilityConfig(is_resumable=True) so every customer decision point pauses cleanly via RequestInput and resumes with typed state.

3. Proposed SQLite Database Schemas

All store, nutritional, inventory, customer, and finalized shopping-list records live in a normalized SQLite database (data/grocery_store.db). Every SKU stores canonical base-unit conversion factors (g, ml, or count) so nutrition and package math are 100% deterministic.

3.1 Product Catalogue & Nutritional Facts

CREATE TABLE products (
    sku                     TEXT PRIMARY KEY,              -- e.g. 'SKU-CHK-BRST-16OZ'
    name                    TEXT NOT NULL,
    canonical_ingredient    TEXT NOT NULL,                 -- 'chicken_breast'
    category                TEXT NOT NULL,
    brand                   TEXT,
    package_qty             REAL NOT NULL,                 -- 1.0
    package_unit            TEXT NOT NULL,                 -- 'lb', 'oz', 'count'
    base_unit               TEXT NOT NULL CHECK (base_unit IN ('g', 'ml', 'count')),
    grams_or_ml_per_package REAL NOT NULL,                 -- 453.592
    unit_price_usd          REAL NOT NULL,
    allergen_tags_json      TEXT NOT NULL DEFAULT '[]',    -- '["gluten","soy"]'
    dietary_tags_json       TEXT NOT NULL DEFAULT '[]',    -- '["gluten_free","low_sodium"]'
    is_active               INTEGER NOT NULL DEFAULT 1,
    updated_at              TEXT NOT NULL
);

CREATE TABLE nutritional_facts (
    sku                     TEXT PRIMARY KEY REFERENCES products(sku),
    serving_size_desc       TEXT NOT NULL,                 -- '4 oz (112g)'
    serving_size_g_or_ml    REAL NOT NULL,
    calories_per_100        REAL NOT NULL,
    protein_g_per_100       REAL NOT NULL,
    carbs_g_per_100         REAL NOT NULL,
    fat_g_per_100           REAL NOT NULL,
    saturated_fat_g_per_100 REAL NOT NULL,
    fiber_g_per_100         REAL NOT NULL,
    sugar_g_per_100         REAL NOT NULL,
    sodium_mg_per_100       REAL NOT NULL,
    data_source             TEXT NOT NULL DEFAULT 'USDA_FDC_SEED'
);

3.2 Inventory, User Profiles & Finalized Meal Orders

CREATE TABLE inventory (
    store_id        TEXT NOT NULL DEFAULT 'STORE-001',
    sku             TEXT NOT NULL REFERENCES products(sku),
    qty_on_hand     INTEGER NOT NULL CHECK (qty_on_hand >= 0),
    qty_reserved    INTEGER NOT NULL DEFAULT 0 CHECK (qty_reserved >= 0),
    aisle_location  TEXT NOT NULL,
    restock_eta     TEXT,
    last_counted_at TEXT NOT NULL,
    PRIMARY KEY (store_id, sku)
);

CREATE VIEW v_available_inventory AS
SELECT store_id, sku, (qty_on_hand - qty_reserved) AS available_qty, aisle_location, restock_eta
FROM inventory;

CREATE TABLE users (
    user_id               TEXT PRIMARY KEY,                -- 'cust_malcom_munson'
    full_name             TEXT NOT NULL,
    phone_number          TEXT,
    cooking_skill_level   TEXT NOT NULL DEFAULT 'intermediate'
                          CHECK (cooking_skill_level IN ('beginner', 'intermediate', 'advanced')),
    default_servings      INTEGER NOT NULL DEFAULT 2,
    daily_calorie_target  INTEGER,
    daily_sodium_limit_mg INTEGER,                         -- e.g. 1500
    created_at            TEXT NOT NULL,
    updated_at            TEXT NOT NULL
);

CREATE TABLE user_dietary_constraints (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id         TEXT NOT NULL REFERENCES users(user_id),
    constraint_type TEXT NOT NULL CHECK (constraint_type IN ('medical_condition', 'allergen', 'diet_regime')),
    code            TEXT NOT NULL,                         -- 'celiac_disease', 'gluten', 'hypertension'
    severity        TEXT NOT NULL CHECK (severity IN ('hard_block', 'warn_threshold')),
    notes           TEXT,
    UNIQUE(user_id, constraint_type, code)
);

CREATE TABLE user_preferences (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id           TEXT NOT NULL REFERENCES users(user_id),
    category          TEXT NOT NULL CHECK (category IN ('cuisine', 'ingredient', 'protein', 'flavor_profile', 'equipment')),
    value             TEXT NOT NULL,                       -- 'mediterranean', 'chicken', 'eggplant'
    sentiment         TEXT NOT NULL CHECK (sentiment IN ('like', 'prefer', 'dislike', 'avoid')),
    weight            REAL NOT NULL DEFAULT 1.0,
    source_session_id TEXT,
    updated_at        TEXT NOT NULL,
    UNIQUE(user_id, category, value)
);

CREATE TABLE meal_orders (
    order_id               TEXT PRIMARY KEY,
    user_id                TEXT NOT NULL REFERENCES users(user_id),
    session_id             TEXT NOT NULL,
    recipe_title           TEXT NOT NULL,
    servings_count         INTEGER NOT NULL,
    recipe_json            TEXT NOT NULL,
    nutrition_summary_json TEXT NOT NULL,
    estimated_total_usd    REAL NOT NULL,
    delivery_channel       TEXT NOT NULL DEFAULT 'account_attached',
    status                 TEXT NOT NULL DEFAULT 'finalized',
    created_at             TEXT NOT NULL
);

CREATE TABLE meal_order_items (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id           TEXT NOT NULL REFERENCES meal_orders(order_id),
    sku                TEXT NOT NULL REFERENCES products(sku),
    required_qty_base  REAL NOT NULL,
    packages_to_buy    INTEGER NOT NULL,
    display_qty        TEXT NOT NULL,
    line_total_usd     REAL NOT NULL,
    deselected_by_user INTEGER NOT NULL DEFAULT 0,
    deselect_reason    TEXT
);

4. Area 1 — Tool & Interface Design

Every lookup, dietary check, math conversion, and database write is encapsulated in typed Python tools with Pydantic schemas so LLMs never perform arithmetic or guess inventory availability.

ModuleTool / NodeDeterministic Responsibility
profile_tools.pyget_user_profile, upsert_user_preference, set_cooking_skill_levelRead/write customer medical constraints, taste preferences, and cooking skill level.
catalog_tools.pysearch_products, find_safe_substitute_skuQuery active in-stock SKUs with deterministic SQL allergen exclusion & dietary tag filtering.
nutrition_tools.pyconvert_units_to_base, get_sku_nutrition, calculate_recipe_nutritionCompute exact per-serving & total calories, protein, carbs, fat, fiber, and sodium from nutritional_facts.
safety_tools.pycheck_dietary_complianceHard-block any SKU intersecting hard_block allergens; flag sodium threshold exceedances.
shopping_tools.pybuild_shopping_list, apply_deselections, save_meal_orderScale ingredients by servings, ceiling-round to purchasable packs, record deselected owned items, persist order.
Future UI Readiness: Every workflow node emits typed Pydantic JSON in Event.output alongside readable Markdown in Event.content. Combined with agents-cli's built-in A2A surface, a future web/mobile UI or A2UI card renderer can bind directly to the shopping list and recipe schemas.

5. Area 2 — Orchestration & Logic

Graph-Enforced Stage Gating

ADK 2.0 Workflow edges prevent skipping stages: sizing cannot run until Gate 1 confirms a meal; checkout cannot run until Gate 3 confirms item deselections.

Loop-Safe HITL Interrupts

Enabled via ResumabilityConfig(is_resumable=True) and indexed RequestInput(interrupt_id=...) keys so customers can iterate on meal ideas, servings, or owned-item removals without restarting.

Self-Healing Safety Loop

validate_meal_safety routes unsafe_allergen back to recipe_author_agent (bounded retries) with safe in-stock SKU substitutes (e.g., GF tamari for soy sauce).

Runner-Wide Guardrail Plugin

DietarySafetyPlugin(BasePlugin) (adapted from safety-plugins) enforces allergen blocking and non-medical-advice disclaimers across every agent and tool centrally.

7. Area 4 — Observability & Tracing

Full OpenTelemetry span hierarchy emitted natively by ADK 2.0 and enriched by an ObservabilityPlugin(BasePlugin):

invoke_workflow (meal_planner_workflow)                      [user.id, session.id, prompt.version]
  ├── execute_node: load_user_context                        [constraints.count, skill_level]
  ├── invoke_agent: meal_discovery_agent                     [workflow.stage="meal_selection"]
  │     ├── call_llm -> generate_content                     [model, input_tokens, output_tokens]
  │     └── execute_tool: upsert_user_preference             [category, sentiment]
  ├── invoke_agent: recipe_author_agent                      [workflow.stage="recipe_authoring"]
  ├── execute_node: validate_meal_safety                     [workflow.route="safe"|"unsafe_allergen"]
  ├── execute_node: compute_nutrition_and_scale              [servings, kcal_per_serving, sodium_mg]
  ├── execute_node: map_inventory_skus                       [sku_count, substitutions_count]
  └── execute_node: persist_meal_order                       [order_id, deselected_count, total_usd]
Local & Production Exporters: Prototype writes traces to logs/traces.jsonl and supports standard OTLP HTTP (http://localhost:4318/v1/traces) for local Arize Phoenix or Jaeger inspection. Cloud deployments activate Cloud Trace (otel_to_cloud=True) and optional BigQuery Agent Analytics (--bq-analytics) with zero code changes.

8. Area 5 — Infrastructure & CI/CD

  • Version Control Everything: System prompts live in versioned Markdown files (app/prompts/*.v1.md) tagged on trace spans; schemas, SQLite migrations (data/migrations/), workflow graphs, tools, and eval datasets are all tracked in Git.
  • Isolated Environment: Scaffolded via agents-cli scaffold create meal-planner --agent adk_python --prototype with a dedicated uv virtual environment and locked dependencies (uv.lock).
  • Two-Layer Quality Gate:
    1. uv run pytest — 100% deterministic unit & integration tests (DB integrity, nutrition math, allergen hard-blocks, SKU rounding, deselection audit trail).
    2. agents-cli eval run — Behavioral & trajectory evaluation against versioned datasets in tests/eval/ with strict pass/fail thresholds (safety == 1.0, trajectory >= 0.90).
  • Seamless Cloud Promotion: Run agents-cli scaffold enhance . --deployment-target cloud_run (or agent_runtime) and --cicd-runner github_actions (or google_cloud_build) when moving beyond prototype.
