# Agent Spec: Grocery Store Recipe Planner & Shopping List Workflow

## Overview
A Google ADK 2.0 (`google.adk.workflow.Workflow`) conversational agentic workflow for a grocery store that helps customers plan healthy meals and build purchase-ready shopping lists grounded in real store inventory and nutritional facts.

The workflow enforces four gated stages via an ADK 2.0 graph DAG with resumable Human-in-the-Loop (HITL) interrupts and maximizes determinism by offloading database queries, allergen/sodium validation, serving/macro math, SKU package sizing, and checkout persistence to typed Python `FunctionNode`s and `FunctionTool`s:
1. **Profile Hydration & Meal Selection Gate**: Greets the user (`"Hello! What are you hungry for?"`), recalls cross-session dietary needs/preferences/skill level, and either accepts a specific requested meal (e.g., `"kung pao chicken"`) or asks clarifying questions and suggests options until the user confirms a meal.
2. **Sizing, Recipe Adaptation & Nutrition Guidance Gate**: Generates/adapts a recipe matching the user's cooking skill level and dietary rules, deterministically computes per-serving and total calories/macros/sodium from the store nutrition database, and gates on the user choosing how many meals/servings to make.
3. **Inventory SKU Mapping & Deselection Gate**: Deterministically maps scaled recipe ingredients to in-stock store SKUs, rounds to purchasable package quantities, and lets the user deselect items they already own (e.g., cumin powder) before confirming.
4. **Checkout & Delivery**: Persists the finalized shopping list (including audit trail of deselected items) and complete recipe to the customer's account in the `meal_orders` / `meal_order_items` database and returns the complete recipe plus finalized shopping list.

## Language
`python` (Python >= 3.11, managed via `uv`, scaffolded with `agents-cli --agent adk_python --prototype` in `meal-planner/`).

## Architecture & Sub-Agents
**Pattern:** Option A — ADK 2.0 Graph `Workflow` (`root_agent = Workflow(...)`) with `App(name="app", root_agent=root_agent, resumability_config=ResumabilityConfig(is_resumable=True), plugins=[DietarySafetyPlugin()])`.

- **Deterministic `FunctionNode`s:**
  - `load_user_context`: Loads structured profile, medical/allergen constraints, preferences, and skill level from SQLite + ADK session/memory state.
  - `validate_meal_safety`: Deterministically blocks unsafe allergens/conditions (e.g., gluten for celiac) and flags high-sodium ingredients (`> threshold`) before a recipe or SKU reaches the user; loops back to recipe adaptation on violation.
  - `compute_nutrition_and_scale`: Deterministically converts recipe ingredient quantities into per-serving and total calories, protein, carbs, fat, fiber, and sodium using `nutritional_facts` and scales by chosen `servings_count`.
  - `map_inventory_skus`: Deterministically resolves canonical ingredients to available `products` + `inventory` SKUs, substitutes dietary-safe alternatives when required (e.g., gluten-free tamari instead of wheat soy sauce), computes package counts and estimated price.
  - `apply_list_edits`: Deterministically removes user-deselected SKUs (recording `deselected_by_user=1`, `deselect_reason='already_owned'`) and recalculates estimated total.
  - `persist_meal_order`: Writes finalized recipe + shopping list to SQLite `meal_orders` & `meal_order_items`, updates learned preferences in SQLite + ADK memory, and emits the final formatted response.
- **Scoped `LlmAgent` Nodes (creative/conversational only):**
  - `meal_discovery_agent`: Friendly greeting, preference-aware Q&A, meal ideation, and extracting new preferences/skill cues; exits gate only once a meal is selected.
  - `recipe_author_agent`: Authors or adapts a structured `RecipeDraft` (Pydantic `output_schema`) calibrated to the customer's `cooking_skill_level` (`beginner` | `intermediate` | `advanced`) and dietary rules; receives deterministic violation feedback if `validate_meal_safety` routes back for revision.
- **Runner-Wide Plugin:**
  - `DietarySafetyPlugin(BasePlugin)`: Enforces hard allergen/celiac blocking on tool outputs and LLM responses, enforces non-medical-advice disclaimer whenever medical dietary conditions (e.g., celiac, hypertension) are present, and attaches domain attributes to OpenTelemetry spans.

## Example Use Cases
1. **Returning customer with medical dietary constraints (Malcom Munson)**
   - *Context in memory/DB:* `user_id=cust_malcom_munson`, celiac disease (`gluten: hard_block`), high blood pressure (`sodium_mg_per_serving <= 600` warning/target, `daily_sodium_limit_mg=1500`), likes Mediterranean food, prefers chicken over fish, dislikes eggplant, `cooking_skill_level=intermediate`.
   - *Input:* `"Hi, I don't know what to make for dinner tonight."`
   - *Expected flow:* Agent greets warmly, proposes gluten-free, low-sodium Mediterranean chicken dishes (no eggplant, no fish), user picks Lemon Herb Chicken Souvlaki Bowls for 4 meals, deterministic tools compute nutrition (e.g., ~480 kcal, 42g protein, 38g carbs, 16g fat, 410mg sodium/serving), maps to in-stock GF SKUs, user removes olive oil & oregano (already owned), agent attaches order to `cust_malcom_munson` and outputs full recipe + shopping list + medical disclaimer.
2. **Direct meal request with no stored restrictions (Guest / new user)**
   - *Input:* `"I want to make kung pao chicken for 2 meals, and I'm a beginner cook. Also I hate super spicy food."`
   - *Expected flow:* Agent greets, acknowledges `"kung pao chicken"`, saves `cooking_skill_level=beginner` and `dislike: spicy` to user profile/memory, generates a simplified mild kung pao chicken recipe, deterministically computes nutrition & scales to 2 servings, maps to in-stock SKUs, user deselects `cumin_powder` / `soy_sauce` they already own, agent persists order and outputs final recipe + shopping list.
3. **Allergen violation caught & auto-remediated**
   - *Input:* Customer with celiac disease requests `"kung pao chicken"`.
   - *Expected flow:* `validate_meal_safety` detects standard wheat soy sauce (`allergen_tags` contains `gluten`) and routes back to `recipe_author_agent` / deterministic SKU mapper to substitute certified gluten-free tamari; no gluten-containing SKU ever enters the shopping list.
4. **Cross-session memory restoration**
   - *Session 1:* User says `"I'm vegetarian and I hate mushrooms; keep recipes easy."`
   - *Session 2 (new session ID, same `user_id`):* User says `"What should I make?"` -> Agent recalls vegetarian hard constraint, mushroom dislike, and beginner skill level without asking again.

## Tools Required
All tools are deterministic Python `FunctionTool`s / `FunctionNode`s backed by a local SQLite database (`data/grocery_store.db`, no external API auth required in prototype mode):
- `get_user_profile(user_id: str) -> dict`: Reads `users`, `user_dietary_constraints`, and `user_preferences`.
- `upsert_user_preference(user_id: str, category: str, value: str, sentiment: str, session_id: str) -> dict`: Persists newly discovered preferences or skill level updates across sessions.
- `search_products(query: str, dietary_tags: list[str], exclude_allergens: list[str], in_stock_only: bool) -> dict`: Queries `products` joined with `v_available_inventory` filtered deterministically by allergen exclusions and stock.
- `get_sku_nutrition(sku: str, quantity_g_or_ml: float) -> dict`: Deterministically computes exact calories, protein, carbs, fat, saturated fat, fiber, sugar, and sodium for a given SKU and gram/ml quantity from `nutritional_facts`.
- `calculate_recipe_nutrition(ingredients: list[IngredientSpec], servings: int) -> dict`: Aggregates per-ingredient nutrition deterministically and returns per-serving and total nutritional breakdown plus sodium/allergen compliance flags.
- `check_dietary_compliance(user_id: str, skus: list[str], nutrition_per_serving: dict) -> dict`: Hard-blocks any SKU containing a `hard_block` allergen for `user_id` and flags any `warn_threshold` (e.g., sodium) breaches.
- `build_shopping_list(ingredients: list[IngredientSpec], servings: int, user_id: str, store_id: str) -> dict`: Scales quantities by `servings`, selects safe in-stock SKUs, rounds up to integer purchasable packages, and calculates line & total prices.
- `save_meal_order(user_id: str, session_id: str, recipe: dict, nutrition: dict, items: list[dict]) -> dict`: Persists finalized shopping list and recipe to `meal_orders` and `meal_order_items` and returns `order_id`.
- `PreloadMemoryTool` (ADK built-in, adapted from `cross-session-memory`): Loads episodic memories across sessions.

## Constraints & Safety Rules
1. **Hard Allergen & Medical Diet Blocking:** No SKU whose `allergen_tags_json` intersects a user's `hard_block` constraints (e.g., `gluten` for celiac disease, `peanuts`, `shellfish`) may appear in a finalized shopping list or recipe recommendation. Enforced deterministically in `check_dietary_compliance` AND verified in `DietarySafetyPlugin.after_tool_callback` / `after_model_callback`.
2. **Sodium & Threshold Guardrails:** For users with `hypertension` / `low_sodium` constraints, any recipe exceeding per-serving sodium limits (`daily_sodium_limit_mg * 0.35`, default `<= 600mg/serving`) triggers a deterministic warning and automatic low-sodium substitution attempt.
3. **Medical Disclaimer:** Whenever a user has a medical condition on file or asks medical-diet questions, the response MUST include a concise non-medical-advice disclaimer (enforced via `DietarySafetyPlugin`).
4. **Deterministic Math Only:** The LLM must NEVER manually compute calories, macronutrient totals, sodium totals, ingredient scaling, or package prices — all numerical calculations are executed exclusively by deterministic Python tools.
5. **Strict Stage Gating:** The workflow cannot proceed to sizing/SKU mapping until a meal is confirmed by the user, and cannot persist a `meal_order` until the user has had an opportunity to review and deselect items they already own.
6. **Inventory Grounding:** Shopping list items must reference real `sku` primary keys from `products` with `available_qty > 0` (or explicitly flag out-of-stock substitutions).

## Success Criteria
1. **Dietary Safety Compliance (Pass/Fail = 100%):** 0% allergen leakage across all evaluation cases involving medical/allergen constraints (e.g., celiac, nut allergy) verified by deterministic tool assertions and LLM-as-judge `safety` metric (`>= 1.0`).
2. **Deterministic Math Accuracy (Pass/Fail = 100%):** 100% exact match between tool-computed calories/macros/sodium/scaled package counts and ground-truth SQLite calculations across unit tests (`uv run pytest`).
3. **Workflow Stage Gating & Trajectory (`agents-cli eval run`):** Tool trajectory match `>= 0.90` and response quality `>= 0.85` across core scenarios (Malcom Munson returning user, direct kung pao chicken request, item deselection, allergen substitution, cross-session recall).
4. **Cross-Session Memory Restoration (Pass/Fail = 100%):** Preferences, dietary constraints, and skill level saved in Session 1 are deterministically recalled and applied in Session 2 without re-prompting.
5. **OpenTelemetry Trace Completeness (Pass/Fail = 100%):** Every workflow run emits linked OpenTelemetry spans covering `invoke_workflow`, every `invoke_agent` / `FunctionNode`, `call_llm`, `execute_tool`, and custom state-transition attributes (`workflow.stage`, `workflow.route`, `user.id`).

## Assumptions
- **Project Directory:** Scaffolded with `agents-cli scaffold create meal-planner --agent adk_python --prototype` as a subdirectory inside this repository, preserving `workflow_prompt.md` and `docs/`.
- **Virtual Environment:** Managed cleanly by `uv` (`meal-planner/.venv` via `uv sync`), installing `google-adk >= 2.0.0` alongside OpenTelemetry local exporters and `aiosqlite`/`sqlalchemy` for SQLite persistence.
- **Model:** Uses the default Gemini model configured by the `agents-cli` scaffold (no hardcoded legacy models); authentication configured via `.env` (Vertex AI ADC or `GEMINI_API_KEY`).
- **Seed Database Size:** Seed script will populate SQLite with ~80–120 realistic grocery SKUs across all major departments (including gluten-free, low-sodium, vegetarian, and standard variants), full 1:1 `nutritional_facts`, realistic `inventory`, and a test fixture user suite (including Malcom Munson).
- **Local OTel Collector / Viewer:** Local prototype exports OpenTelemetry traces via `ConsoleSpanExporter` / JSONL trace log and optional OTLP (`http://localhost:4318/v1/traces` for Arize Phoenix or Jaeger), while preserving `otel_to_cloud=True` hooks for future Cloud Trace.
